## 2. OCR 标准流程（扫描版，省钱版）

1. **渲染 150dpi**：pymupdf `fitz.Matrix(150/72,150/72)` → .work/<slug>_pages/page_NNN.png
2. **PaddleOCR-VL 快扫**：模型 `PaddlePaddle/PaddleOCR-VL-1.5`，6 并发，逐页转写 → dev_ocr.txt + 进度文件
3. **清洗**（必做）：删 `<|LOC_数字|>` 布局标记
4. **乱码检测**（必做）：Unicode 块检测（西里尔/希腊/孟加拉/泰米尔/天城体/阿拉伯/泰文/韩文/日文假名）→ 重污染页（>1%）列清单
5. **32B 精修**：Qwen3-VL-32B，4 并发，重跑重污染页 + 短页（<50 字符）+ 语义受损页（维果茨基节这类）
6. **复查**：乱码检测再跑一遍，0 残留才算过
7. **抽查**：每章中段抽 1-2 页人工/32B 复核

### 关键参数（抄作业）
- PaddleOCR：model=PaddlePaddle/PaddleOCR-VL-1.5, max_tokens=4000, 并发 6（429 限流时降 3）
- 32B：model=Qwen/Qwen3-VL-32B-Instruct, 并发 4, 每页重试 3 次
- 断点：进度文件（已处理页码），kill 后重跑自动跳过

## 3. 阶段流程（0-5，每阶段有门禁）

### 阶段0 骨架（Adler）
- 输入：目录/内容提要/前言 + 抽样正文
- 产出：BOOK_OVERVIEW.md（结构/术语/命题/批判/应用潜力）
- **门禁**：用户确认骨架（一句话主旨 + 章节结构 + 技能划分）——确认后才进阶段1
- 省钱：主会话 flash 起草 → 1 个 pro 子代理核验（可选，大书做）

### 阶段1 提取
- 输入：章节文件（.work/chapters/chXX.txt，按目录页范围拆分，偏移=书页→PDF页）
- 小书（<15 万字符）：**主会话直接读关键章提取**（已验证 gottman/makestick 可行，省时省钱）
- 大书（>30 万字符）：5 类提取器子代理分批（每批 ≤4 个，每代理 1-2 章）
- 产出：candidates/（frameworks/principles/cases/counter-examples/glossary）
- **门禁**：候选池数量达标（框架≥30/原则≥40/术语≥50 等），不够主会话补写

### 阶段1.5 验证
- 程序化：按 id 去重合并 → verified.md
- 主会话复核：候选质量（有原文引用 + 家长价值 + 非常识）
- **必做路由验证**：机器词表初判（blindtest_lexicon_mock_v1.py，¥0）→ 无锚/弱锚/邻族抢单的子集才派 1 个 judge 子代理（单发！）做结构化判定（12-15 条口径不变，机器先筛；免 LLM 仅限 机器机械可判且 top1=目标 的路由）
- 产出：verified.md + 盲测报告

### 阶段2 构造（RIA++）
- **主会话直接写**（已验证：六段齐全 + CHECKPOINT + 输出结构，质量过盲测）
- 每个技能：frontmatter（name/description 含做什么+何时用+触发词）+ R/I/A1/A2/E/B + 🔴CHECKPOINT + 回答输出结构
- description 写让位规则（与相邻技能消歧）+ 医疗/危机边界
- **门禁**：frontmatter 校验（name 合法 + description 有触发词）+ 无空话尾巴

### 阶段3 链接
- INDEX.md（技能总览 + 引用图 + 交叉引用约定）
- GLOSSARY.md（术语词典，家长版 30 条起）

### 阶段4 测试
- test-prompts.json：每技能 3 条（应调用/诱饵/跨技能路由），含医疗 none + 危机 + ADHD 路由
- 主会话自查路由 → 机器词表初判 → **judge 结构化复核**（单发，只跑 needs_llm 子集）→ 修复（hill-climbing）→ 同步

### 阶段5 交付
- DIGEST.md（精华长文）+ 安装两工作区（家庭教育 + PPT制作）
- 四件套：SKILL + BOUNDARIES + INDEX + GLOSSARY

## 4. 子代理调度与三闸失败协议（防卡死，血泪教训 + 机器化）

⚠️ 原教训：15 个提取器并发卡 13 个、3 个构造器全卡；fishpond/黑天鹅/非对称风险/随机漫步 ≥6 次 judge 大并发或长任务零产出 → 主会话降级 → 事后补签 9/9 全量返工。

1. **机械层先行**：凡确定性可判（引文逐字/页锚/池 id/引号冒充/结构规则/触发词命中）一律本地脚本，零 LLM、可重跑、不卡死；机器报告落 schema JSON（命中/缺项候选/证据行号/扣分建议）。
2. **LLM judge 只跑语义窄域**：输入=机器证据包（KB 级），单发小批（每批 1 个 judge，盲测只跑 needs_llm 子集），prompt 自包含+绝对路径+只读。
3. **提取/OCR 子代理并发**：每次最多 3-4 个不超 5（原纪律保留）；每任务自包含、写文件用绝对路径。
4. **超时协议（机器化版）**：子代理/judge 约 20-30 分钟无产出 → send_message 询问一次 → 仍无 → interrupt 后重派 1 次或换通道（SiliconFlow 32B 后备）→ **连续 2 次无产出 = 该闸 gate-blocked 挂起**（不是主会话降级接盘）：批量跳过该书继续，收尾状态机 passed/pending/blocked 交用户（§13）。
5. **小任务**（单个技能/单章提取）直接主会话做，不派子代理（原纪律保留）。
6. **补闸纪律**：补闸只补语义窄域；机器层已放行项不返工（机器命中项不因 judge 重评翻案，消除 A-补签 9/9 型全量返工链）。

## 7. 踩坑对照表（抄作业）

| 坑 | 对策 |
|---|---|
| 子代理大并发卡死 | ≤4/批 + 超时接管（§4） |
| SiliconFlow 32B 慢/500 | 只用 32B 修问题页；PaddleOCR 快扫主体 |
| PaddleOCR 乱码 + <\|LOC\|> | 清洗标记 + Unicode 乱码检测 + 32B 重跑 |
| JS 模板字符串转义报错 | 内容用数组 join 或写 python 文件，避免反引号/ASCII 引号 |
| pwsh here-string 转义 | 长内容用 write 工具写 py 文件再执行 |
| pnpm 构建脚本报错中断插件安装 | 手动补 bundles |
| 子代理输出路径错误 | prompt 给绝对路径，写后主会话验证文件存在 |
| 分类页/图页 OCR 超短 | 32B 复核，标注「图页」或补跑 |
| 章节拆分偏移错 | 用目录页页码验证（书页=PDF页-偏移） |
| 忘记录/忘同步 | 每阶段更新 PIPELINE_STATE + 同步两工作区 |
| judge 长任务/大并发卡死 | 机器层先行 + judge 只跑语义窄域；连续 2 次无产出 → gate-blocked 挂起（§4/§13） |
| 同型问题 judge 幅度漂移（池族缺映射 -1~-3） | 机器统一规则触发，judge 只做例外豁免与幅度校准 |
| 机器误把书内引文当 AI 腔 | d7 扫描豁免 R 段/「」引句/引用块（v2 已修） |

## 10. L2.5 混合档位（2026-09-03 试点验证，承重墙书默认档）

> 背景：双路线对比实验（我的裸流程 vs 仓颉完整线A，3/3 judge）证实——仓颉强在"建体系"（多路提取覆盖+淘汰验证+页码溯源），我强在"快出裁决"（整书裁决链），费用大头是 cacheRead（重复读书）。L2.5 取两者之长：**共享精读笔记把"读 N 遍全书"降为"读 1-2 遍 + N 路审阅"，用 1/2-1/3 成本达 L3 的 85-95% 质量**。
> 试点实证：《货币放水的尽头》（10章/250页）16 子代理 ¥1.56，6 技能过达尔文 81.4 分基线，34 引文逐字核验一致。

### 10.1 档位选择（书的价值决定档位）

| 档位 | 适用 | 流程 | 单本粗估 | 相对L3 |
|---|---|---|---|---|
| L1 速读卡 | 背景书/历史书群 | 摘录卡 + 防线1/3 | ¥2-5（实测校准） | ~1/5 |
| **L2.5 体系卡（默认）** | 承重墙书 | §10.2 七步 | ¥15-25（文字版 3 技能，含 B 档+复验，2026-09-06 实测）／¥8-12（1 技能） | 1/2-1/3 |
| L3 旗舰 | 值得反复读的书 | 仓颉完整线A | ¥10-20（估算，未实测） | 1x |

### 10.2 L2.5 七步管线

```
步骤1：PDF→章节文本（.work/chapters 模式）                    [最便宜]
步骤2：阶段0 BOOK_OVERVIEW + 带页码精读笔记（全书读1-2遍）
       ——"宁可多不可少"全量摘录（150-450条/本），每条带[pNN]页码
       这是质量地基，5路提取器共享，勿偷工                    [全书1-2遍=最大单项]
步骤3：5路提取器（framework/principle/case/counter-example/glossary）
       ——基于精读笔记审阅+原文抽查，不各自通读全书           [省60-70%读书费]
步骤4：三重验证(V1/V2/V3) + 目录覆盖检查(防线4)               [轻]
步骤5：RIA++构造（按主题聚合为N个整书级技能）
       ——限定语存疑候选必须条件式改写                        [写作成本]
步骤6：忠实度核验关(防线3)：独立judge带原书核对
       R段引文逐字 + 核心主张 + 操作层冒充检查 → 修复→复验    [¥0.5-1，必做]
步骤7：达尔文9维质量关（基线评分，triage用）                  [¥0.5-1]
```

### 10.3 L2.5 关键纪律（试点血泪）

1. **提取器的"限定语损失"盲区是系统性弱点**：只读笔记会把作者条件句提取得更绝对——靠"步骤4标记存疑 + 步骤5条件式改写 + 步骤6核验独立确认"两级补住，不许省；
2. **精读笔记宁多勿少**：笔记筛选偏差是最大风险，全量摘录+带页码可回查；
3. **并行构造 ≤4-6 个/批**（遵守 §4 并发纪律），prompt 给主题关键词让代理自主从 verified.md 选单元（勿手工对齐 id）；
4. **书体裁影响覆盖**：历史案例体（案例密度高）与信条体（互锁）对提取器压力不同——案例体注意 case 池与主池的边界；
5. **时代局限必标**：宏观/政策类书写作年代与当前差距大（如 2013 书 vs 2020s），技能 B 段必须诚实标注"已证伪/已改变"处，并给〔需独立取数〕纪律（§10.4）。

### 10.4 家族级交付标准（试点后固化）

- 每个技能补「数据更新指引（2020s）」节：3-5 个可检索更新指标，写明"不得照搬书内旧数据当现状"
- 每个技能 E 段附 1 个成品输出示例（标注"示例非实时判断"）
- related_skills 必须回填**实际存在**的兄弟 slug（试点曾出现 5-6 个别名指向不存在目录）
- 输出形态定位：宏观/政策类技能 = "环境判断+风险认知"，统一拒时点与买卖指令

### 10.5 构造质量内建 + 机器初评前置（2026-09-10 升级 + 三闸机器化版）

> 原教训保留：构造→评分→修复的返工循环里，静态可自查项占扣分 ~80%，第一次就该清零；rubric 维度是构造时的验收标准，不是第三方事后查。

#### 三级防返工闭环（试点后固化）
1. **构造自查（¥≈0，原 §10.5 保留）**：构造代理交卷前跑 9 维自查表 + 自走查（test-prompts dry-run），不合格不发。
2. **机器初评（闸门层，¥0）**：machine_precheck_v2.py 跑 9 维机械规则（d1-d7/d9；d8 实测除外，证据行号 + 扣分候选，semantic_only_notes 显式标出）。试点 A（n=6）：机器触发 7/7 与独立 judge 同向、0 误报；机械类理由 100% 可同源复现；同源问题（池族缺文件映射）六卡 judge 幅度 -1~-3 漂移被机器统一规则钉住。
3. **LLM 复核（语义兜底）**：judge 只读机器证据包判语义残差（d1 语义重复/d2 颗粒度/d4 介入粒度/d5 排版/d6 行文/d7 回声体积）+ d8 实测 + 幅度校准；前两级全绿则 LLM 只做 d8 + 校准，单次成过。

#### 效果预期（机器化版）
- 结构维度（59 分）：自查清静态项 + 机器初评复查 → 首次机器静态机械分基线即高位（试点：rse 75.1 / trv 75.8 / 六卡 72.2-77.0）；judge 只保留其语义打磨扣分（六卡 Δ +2.7~+8.6，均为语义域）。
- 评分后修复从必修 3 项降到语义残差 1-2 项；机器命中项不再返工。
- dim8 仍需 full_test 坐实（流程固有成本，不因内建消失）。

#### 质量内建的账（含机器层的账，试点实测）
| | 前端自查 | 机器初评 | 评分后修复（后端） |
|---|---|---|---|
| 费用 | +¥0.05-0.15/技能 | ¥0（本地 py） | −¥0.1-1.6/次返工（原账本实测） |
| 时间 | +几分钟 | +秒级 | +2-3 轮子代理串行等待 |
| 效果 | 静态项归零 | 三闸机械层全绿、证据可复验 | 修完需复验、可能再发现 |
| 净结论 | 前端+机器层合计约 ¥0.1/技能，省掉返工闭环与 judge 通读全文成本（试点 A/B 全程零 LLM 费用） |

#### 构造四纪律（v3.1，负样本《最优解人生》实测新增）
1. **判停/路由单一规范源**：路由目标（投资/财务/法律/保险/医疗/危机/时点）只在 B1 展开一次；description/A2/步骤0/判停速查只留压缩行并回指 B1，防多副本口径漂移（实测：5 处副本漂移成为 d7 必修）。
2. **超长行折行**：散文段/步骤单行 ≤260 字符；frontmatter description 可用 YAML 续行分段（机器解析器按行拼接，断点选在句读处）。实测：desc 832→845 折 6 行后 d1 仍 pass、词表词元不受影响。
3. **判停速查=正文浓缩**：速查每条须在 步骤0/B1 有对应实现；构造自查时逐条对照（§10.5 原交叉一致性要求，v3.1 起机器 polish_scan_v31.py 提供 warn）。
4. **d4 检查点分段**：复杂卡（步骤≥6）可在步骤3 出口加轻量中间回显（如“阈值/缓冲垫/富余初判”），再在步骤5→6 保留 🔴 总确认点；单一确认点对简单卡够用（rse 先例）。

## 12. 会话纪律、无人值守与 gate-blocked（三闸机器化版）

> 目的：防越蒸越慢（会话膨胀）+ 防 judge 卡死拖垮批量（原 §12 动机保留）；无人值守时三闸以 机械层必过 + 语义层最小化 + gate-blocked 收口（§13），不再依赖主会话降级补签。

### 12.1 一书一提醒（用户在场时）
1. 一本书 = 一个会话批次；每本完成提示开新会话再接下一本（原纪律保留）。
2. 会话开始前自查：本会话已承载过蒸馏/上下文重 → 先提示开新会话，不硬蒸。
3. 子代理回报纪律：任务子代理只回摘要（≤3 行）、全文落文件；质检每波结束向用户给 1 行进度摘要；主会话上下文纪律=报告只保留结论行、全文落盘（v3.2）。
4. 例外：L1 速读卡等轻任务可同会话完成。

### 12.2 无人值守自动接管（用户不在场时）
1. 主会话当主管，按 L2.5 流程逐步推进；步间不等待确认（用户检查点按既定方案自动通过）。
2. 三闸门禁照常且自动化：机器层必过 → 语义 judge 复核 → gates 状态机落盘；不达标自动修复重评（≤2 轮）仍不达标标记 blocked。
3. judge 卡死不再主会话降级：连续 2 次无产出（含换通道）→ 该闸 gate-blocked 挂起 → 批量跳过该书继续 → 收尾汇总 blocked 清单交用户（状态机见 §13）。
4. 防膨胀纪律保留：子代理回报收摘要、全文落文件；单批并发 ≤4-6。
5. 批量结束：每本产物路径+机器静态分+语义复核结论+遗留 blocked 汇总，等你回来确认。

### 12.3 模式关系
- 用户在场 = 12.1；用户不在场 = 12.2；触发词同 v2.3。
- 机器层产物（machine-report/gates JSON）即 12.2 自动续跑的检查依据，也是事后人工复核与仲裁的唯一权威副本。

### 15.2 对比实验设计（两手册蒸馏同一文件）
0. 首轮用单本（L2.5 中档承重墙书）起跑，控制双倍成本；两版共用 §10.5 构造自查基线，三闸门禁是唯一变量。
1. 同一输入文件（书）分别按 v2.3 与 v3.0 各跑一遍（不同会话/不共享中间缓存，防串扰）。
2. 对比指标：总费用（cost-meter 账本）、judge 子代理卡死/接管次数、三闸每闸耗时、机器静态机械分与 judge 分差、盲测 needs_llm 子集大小及其 judge 复核一致率、机器层降级/不适用次数、防线3 修复轮数、最终技能分数、人工复核工作量。
3. 判读规则：v3.0 费用与卡死次数应显著下降；**评分对比须 paired 同 judge**，总分并列展示、不跨 judge 判胜负（本实验 v23 84.9 vs v30 94.9 即跨 judge 口径差，见规范蒸馏对比/对比报告.md）；语义残差清单应能解释两版分数差。
4. **B 档权威终评（v3.1）**：需要“最终技能分”作交付/汇报口径时，用 darwin9-scorecard 派独立 judge 按权威权重表整篇 9 维独立评分（judge_raw 可修正机器 raw，逐维 evidence+必修）；与 A 档（machine_static + 语义层校准合成分）并列展示并注明档位；同 judge 才可比。实测并列（负样本《最优解人生》）：A 机器 77.00 ｜ A 语义层合成分 97.7（judge32c9cb61）｜ B 权威 95.9（judge ce028871，must_fix=0）。
4. 对照结论落盘到 投资蒸馏/三闸机器化/ 后，再决定是否把 v3.0 设为权威并更新 AGENTS.md。
